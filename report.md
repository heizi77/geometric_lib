## 1. Цели и задачи тестирования

**Цель.** Автоматически проверить, что функции расчёта площади и периметра в библиотеке `geometric_lib` возвращают корректные результаты для круга, треугольника, квадрата и прямоугольника.

**Задачи:**

1. Определить наборы входных данных и вручную рассчитать для них ожидаемые результаты.
2. Написать unit-тесты на `unittest` для всех четырёх фигур, не изменяя исходный код фигур.
3. Проверить обычные значения, граничные значения (ноль, дробные числа) и некорректный ввод (отрицательные числа, строки, несуществующий треугольник).
4. Запустить тесты, зафиксировать результаты и проанализировать причины проваленных тестов.
5. Разместить код тестов в общедоступном репозитории.

## 2. Описание тестируемого продукта

`geometric_lib` — набор модулей на Python, каждый из которых описывает одну геометрическую фигуру и содержит функции `area` (площадь) и `perimeter` (периметр).

| Модуль          | Функция                | Формула            | Параметры                           |
|-----------------|------------------------|--------------------|-------------------------------------|
| `circle.py`     | `area(r)`              | π · r²             | `r` — радиус                        |
| `circle.py`     | `perimeter(r)`         | 2 · π · r          | `r` — радиус                        |
| `rectangle.py`  | `area(a, b)`           | a · b              | `a`, `b` — стороны                  |
| `rectangle.py`  | `perimeter(a, b)`      | 2 · (a + b)        | `a`, `b` — стороны                  |
| `square.py`     | `area(a)`              | a²                 | `a` — сторона                       |
| `square.py`     | `perimeter(a)`         | 4 · a              | `a` — сторона                       |
| `triangle.py`   | `area(a, h)`           | a · h / 2          | `a` — сторона, `h` — высота к ней   |
| `triangle.py`   | `perimeter(a, b, c)`   | a + b + c          | `a`, `b`, `c` — стороны             |

Согласно документации (docstring) функций, параметры — числа типа `int` или `float`. Проверка входных данных в коде не заявлена.

## 3. Область тестирования

**В области тестирования:**

- все 8 функций из четырёх модулей: `circle`, `rectangle`, `square`, `triangle`;
- корректность вычислений для целых и дробных значений;
- поведение на граничных значениях (ноль);
- поведение на некорректных входных данных (отрицательные числа, строки, стороны, не образующие треугольник).

**Вне области тестирования:**

- интеграция между модулями (модули независимы друг от друга);
- производительность и нагрузочное тестирование;
- пользовательский интерфейс (его в библиотеке нет).

## 4. Стратегия тестирования

- **Вид тестирования:** модульное (unit) функциональное тестирование методом «чёрного ящика»: тесты проверяют только входы и выходы функций, как если бы исходный код был недоступен.
- **Инструмент:** стандартная библиотека `unittest`. Для каждой фигуры создан класс-наследник `unittest.TestCase`, имена методов начинаются с `test`, проверки выполняются через `assertEqual`, `assertAlmostEqual` и `assertRaises`.
- **Техники проектирования тестов:**
  - *эквивалентное разбиение* — обычные положительные целые и дробные значения;
  - *анализ граничных значений* — ноль;
  - *проверка свойств* — перестановка сторон не меняет результат, при увеличении радиуса вдвое площадь круга растёт вчетверо;
  - *негативные тесты* — отрицательные значения, строки, стороны, не образующие треугольник.
- **Сравнение чисел с плавающей точкой:** `assertAlmostEqual` (для круга, где участвует число π, а также для дробных входных данных).
- **Окружение:** macOS, Python 3.9.
- **Запуск:** `python3 -m unittest test_figures.py -v`.

## 5. Критерии приёмки

Тестирование считается завершённым, а продукт принятым, если выполнены условия:

1. Написаны и выполнены тесты для всех четырёх фигур и обеих функций каждой фигуры.
2. Исходный код фигур не изменён.
3. Все тесты корректного поведения (обычные значения, ноль, дробные числа, свойства) проходят.
4. Тесты, проверяющие защиту от некорректного ввода, либо проходят, либо каждый провал задокументирован как дефект с объяснением причины.
5. Код тестов размещён в общедоступном репозитории, факт появления тестов виден в истории коммитов.

## 6. Ожидаемые результаты

- Все функциональные тесты на корректных данных проходят, то есть 100% совпадение с вручную рассчитанными значениями.
- Для негативных тестов, исходя из документации функций, ожидаемого поведения нет. Предполагается, что библиотека может не проверять входные данные, и такие тесты могут выявить дефекты.
- Результатом тестирования является протокол: общее число тестов, число успешных и проваленных, список обнаруженных дефектов.
- Метрики качества: процент успешных тестов, количество дефектов по фигурам.

## 8. Выводы из результатов тестирования

1. **Расчётная часть работает правильно.** Все тесты на корректных входных данных (обычные и дробные значения, ноль, перестановка сторон, масштабирование радиуса) прошли успешно. Формулы площади и периметра всех четырёх фигур реализованы верно.

2. **Все 11 провалов вызваны одной причиной: в коде нет проверки входных данных.** Функции просто применяют формулу к любым переданным значениям и не сообщают о некорректном вводе. Исходный код при этом не менялся, поэтому проваленные тесты зафиксированы как дефекты, а не исправлены.

3. **Отрицательные размеры принимаются без ошибки** (тесты 1–4, 6, 7, 9, 10). Результаты при этом бессмысленны: отрицательная длина, а для круга и квадрата площадь из-за возведения в квадрат оказывается положительной (`circle.area(-3)` = 28,27, `square.area(-4)` = 16), что скрывает ошибку в данных.

4. **Строки не отвергаются.** Из-за того, что Python умеет умножать строку на целое число, `rectangle.area("ab", 3)` возвращает `'ababab'`, а `square.perimeter("a")` — `'aaaa'` вместо ошибки (тесты 5 и 8). При этом `circle.area("5")` и `square.area("a")` ошибку выдают, так что поведение непоследовательно.

5. **Треугольник не проверяет неравенство треугольника.** `triangle.perimeter(1, 1, 10)` возвращает 12, хотя стороны 1, 1, 10 не образуют треугольник (тест 11).

6. **Соответствие критериям приёмки.** Критерии 1, 2, 3 и 5 выполнены. Критерий 4 выполнен в части документирования: каждый провал описан выше как дефект.

7. **Рекомендации.** Добавить в функции проверку входных данных: для отрицательных значений выбрасывать `ValueError`, для нечисловых типов — `TypeError`, а в `triangle.perimeter` дополнительно проверять неравенство треугольника. После исправления кода те же тесты можно использовать для регрессионной проверки. Без изменения кода фигур (как требует задание) альтернативой может быть уточнение в документации, что функции предполагают корректные положительные числа, и тогда негативные тесты следует считать проверкой за пределами контракта.
